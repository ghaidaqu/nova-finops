# مراجعة خبير FinTech لنموذج ربط NOVA

> التاريخ: 21 أكتوبر 2026 — الاعتماد على مصادر رسمية ووثائق المنتجات.

## القرار التنفيذي

الفكرة صحيحة، لكن صياغة «لا يفعل العميل شيئاً» تحتاج ضبطاً: المطلوب **صفر عمل روتيني** بعد تهيئة أولية قصيرة، وليس صفراً مطلقاً. العميل سيحتاج مرة واحدة إلى الموافقة على الربط، اختيار المنشأة والحسابات، واعتماد اقتراحات المطابقة. بعد ذلك تعمل NOVA وحدها ولا تتواصل معه إلا عند استثناء حقيقي أو انتهاء تفويض.

لا أنصح ببناء «Codat سعودي» منذ البداية، ولا بشراء كل شيء. القرار الأفضل هو نموذج هجين:

- **نشتري/نتشارك** في الوصول المنظّم للبنوك، لأن هذه طبقة ترخيص وامتثال وعلاقات مصرفية وليست ميزة NOVA الأساسية.
- **نبني** نموذج البيانات المالي الموحّد، منطق المطابقة، قواعد الرسوم والتسويات، طابور الاستثناءات، جودة البيانات، وسجل القرار؛ هنا توجد قيمة NOVA وميزتها التنافسية.
- **نبني موصلات محلية قليلة وعميقة** للأنظمة الأكثر استخداماً لدى أول شريحة عملاء، ونستخدم مزوّد تجميع عالمي فقط إذا أثبت أنه يغطي مصادر العملاء فعلاً وبتكلفة أقل من الصيانة.

## ما نبنيه وما نشتريه

| الطبقة | القرار | السبب |
|---|---|---|
| بيانات البنوك السعودية | شراكة مع مزوّد مصرفية مفتوحة خاضع لإشراف/ترخيص ساما | ساما جعلت مشاركة البيانات قائمة على موافقة العميل ومن خلال جهات خاضعة لإشرافها؛ بناء اتصال مصرفي مباشر يضيف عبئاً تنظيمياً وتشغيلياً كبيراً ([ساما](https://sama.gov.sa/en-US/MediaCenter/News/pages/news-1135.aspx)، [إطار المصرفية المفتوحة](https://www.openbanking.sama.gov.sa/index-en.html)) |
| Wafeq | موصل أصلي من NOVA عبر OAuth | Wafeq يوصي بتطبيق OAuth متعدد العملاء مع صلاحيات محدودة وتدوير refresh token؛ تجربة مناسبة لزر «ربط» واحد ([Wafeq](https://developer.wafeq.com/docs/authenticate-and-make-your-first-request)) |
| Odoo | موصل أصلي، لكن ليس أول موصل وحيد | الـAPI الخارجي متاح رسمياً في خطة Custom، ومفاتيحه حساسة؛ يلزم مستخدم bot محدود الصلاحية ومسار بديل لعملاء Standard ([Odoo API](https://www.odoo.com/documentation/19.0/developer/api/external_api.html)، [Odoo pricing](https://www.odoo.com/pricing)) |
| Qoyod / POS / بوابات الدفع | موصلات أصلية حسب طلب العملاء الفعلي | الأولوية للتغطية العميقة لا لعدد الشعارات؛ نبني الموصل عندما يوجد 3–5 عملاء تصميم يحتاجونه |
| البريد والمستندات | OAuth محدود + صندوق استقبال مخصص لكل عميل | يزيل التحويل والرفع اليدوي، لكن لا نجمع كامل صندوق البريد؛ نقرأ label/folder أو alias مخصصاً فقط |
| التطبيع والمطابقة والاستثناءات | نبنيها بالكامل | هذه هي الـIP: تفسير التسوية والرسوم والمرتجعات والفروقات مع أثر تدقيقي واضح |
| إدارة الموصلات العامة | نقيّم Codat/Rutter عند التوسع الدولي | Rutter مثلاً يوفر initial/incremental sync قابلين للضبط، لكنه لا يلغي الحاجة إلى تغطية المصادر السعودية أو منطق NOVA ([Rutter](https://docs.rutter.com/rest/2024-08-31/config-sync)) |
| رفع CSV وNOVA Bridge | fallback فقط | مهم لبدء عميل لا يملك API، لكن لا يصبح تجربة المنتج الأساسية |

## تجربة العميل الصحيحة

1. **جلسة تهيئة واحدة بمساعدة NOVA (20–40 دقيقة):** يختار الأنظمة، يفوض الوصول، ويؤكد الحسابات والكيانات المقترحة.
2. **فحص جودة تلقائي:** تعرض NOVA ما إذا كانت التغطية مكتملة، وما الفترة المتاحة، وأي مصدر ناقص.
3. **تشغيل صامت:** مزامنة دورية + webhooks + retries. لا زر استيراد ولا طلب كشف أسبوعي.
4. **صندوق قرارات واحد:** تعرض فقط: «فرق 215 SAR يحتاج تصنيفاً» أو «انتهى التفويض وأعد الربط».
5. **التعلم من القرار:** القرار المتكرر يتحول إلى قاعدة مقترحة، ولا يصبح قاعدة آلية إلا بعد اعتماد العميل.

الرسالة الأنسب: **«اربط مرة واحدة؛ NOVA تتابع يومياً ولا تعود إليك إلا بقرار.»**

## المعمارية المقترحة

```text
المصادر → موصلات آمنة → مخزن خام غير قابل للتعديل → نموذج NOVA موحّد
                                              ↓
                               مطابقة + قواعد + درجات ثقة
                                              ↓
                             نتائج مؤكدة / طابور استثناءات
```

المكونات الضرورية منذ أول نسخة:

- عزل كامل لكل عميل، وربط كل credential بالمنشأة الصحيحة.
- خزنة أسرار وتدوير مفاتيح، مع صلاحيات قراءة فقط وأقل نطاق ممكن.
- `cursor/checkpoint` لكل موصل، وعمليات idempotent لمنع التكرار.
- الاحتفاظ بالبيانات الخام مع lineage يوضح مصدر كل رقم وتحويلاته.
- نموذج موحّد محدود: `sale, payment, fee, refund, payout, bank_transaction, invoice`.
- محرك مطابقة يدعم 1:1 و1:N وN:1، وفواصل زمنية ورسوم وضرائب.
- لوحة تشغيل داخلية: آخر مزامنة، freshness، أخطاء الصلاحية، نقص التغطية، retries وreplay. هذا يتفق مع نمط Codat في إعادة محاولة وإعادة تشغيل أحداث webhook ([Codat](https://docs.codat.io/using-the-api/webhooks/overview/)).
- سجل تدقيق لكل قاعدة وقرار وتغيير، وإمكانية التراجع.

لا نبني في الـMVP: كتابة قيود إلى النظام المحاسبي، دفع أموال، نماذج ذكاء اصطناعي مستقلة، عشرات الموصلات، أو تطبيق سطح مكتب عام.

## كيف نزيل الرفع والنسيان فعلياً؟

- البنك يصل عبر شريك Open Banking؛ لا كشف حساب.
- برنامج المحاسبة يتزامن تلقائياً؛ لا تصدير Excel.
- إشعارات الموردين والتسويات تصل إلى alias مثل `invoices+client@nova.sa` أو label مفوض؛ لا forwarding أسبوعي.
- المنصة تعيد المحاولة وتنبّه فريق NOVA أولاً؛ العميل لا يتلقى تنبيهاً إلا إذا كانت إعادة الموافقة لا يمكن تنفيذها بدونه.
- عند عدم وجود API: إعداد scheduled export إلى SFTP/مجلد سحابي مرة واحدة. الرفع اليدوي قناة إنقاذ وليس عملية تشغيل.
- NOVA Bridge لا يُبنى إلا إذا أثبتت التجارب وجود مجموعة كبيرة من الأنظمة المحلية/on-premise لا يمكن خدمتها بطرق أبسط.

## خطة MVP مرتبة

### 0. إثبات الطلب — أسبوعان

- اختيار شريحة واحدة فقط (مثلاً مطاعم متعددة الفروع أو تجارة إلكترونية) و3–5 عملاء تصميم.
- حصر مصادرهم الفعلية، حجم العمليات، شكل التسويات، وأكثر 10 استثناءات تكراراً.
- توقيع اتفاق معالجة بيانات وتحديد هدف نجاح رقمي.

### 1. الأساس — 4 أسابيع

- نموذج البيانات الموحّد، المخزن الخام، العزل، سجل التدقيق، مراقبة جودة وربط البيانات.
- موصل واحد لباب الإيراد/الدفع + استيراد بنكي آلي من شريك أو sandbox.
- شاشة داخلية لصحة الربط؛ لا واجهة عميل كبيرة.

### 2. المصالحة — 4 أسابيع

- مطابقة رسوم/دفعات/مرتجعات/تسويات بالقواعد.
- درجات ثقة وطابور استثناءات واحد.
- تقرير يومي مختصر: المتطابق، المعلّق، الأثر النقدي.

### 3. التهيئة الذاتية المحدودة — 2 إلى 4 أسابيع

- زر OAuth لـWafeq أو المصدر المحاسبي الأكثر شيوعاً لدى عملاء التصميم.
- التقاط مستندات عبر alias أو folder محدود.
- تنبيه انتهاء التفويض ومسار إعادة ربط من خطوة واحدة.

### بوابة قرار قبل التوسع

لا نضيف موصلاً رابعاً قبل تحقيق هذه الحدود على عميلين متتاليين:

- أكثر من 95% من الأيام تصل بياناتها دون تدخل بشري.
- أكثر من 80% من العمليات تطابق آلياً في البداية، مع مسار واضح لرفعها إلى 90%+.
- أقل من 10 استثناءات بشرية لكل 1,000 عملية.
- اكتشاف فشل المزامنة داخلياً خلال 15 دقيقة.
- وصول العميل لأول نتيجة موثوقة خلال يوم عمل واحد من الربط.

## المخاطر التي يجب عدم تجاهلها

1. **الترخيص:** إذا أصبحت NOVA نفسها مزوّد خدمة مصرفية مفتوحة، أو بادرت بالدفع/حرّكت الأموال، يتغير النطاق التنظيمي جذرياً. ابدأ read-only عبر شريك مرخّص، وخذ رأياً نظامياً سعودياً قبل إطلاق تجاري؛ لا نفترض أن «تحليل البيانات» يعفي تلقائياً.
2. **PDPL وموقع البيانات:** البيانات المالية قد تتضمن بيانات شخصية. يجب تحديد controller/processor، الغرض، مدة الاحتفاظ، المتعهدين الفرعيين، والاستضافة/النقل خارج المملكة. إرشادات SDAIA تشترط ضمانات للمعالجين وضوابط للنقل الدولي ([دليل PDPL](https://dgp.sdaia.gov.sa/wps/portal/pdp/knowledgecenter/details/PDPLCP/%21ut/p/z1/04_Sj9CPykssy0xLMnMz0vMAfIjo8ziPR1dzTwMgw2MDMOcTA3MjH39TE29jY0MQsz1w9EUhIZZAhUEGvl6OXoaGwQY60cRo98AB3A0IKTfi5ACoA-MinydfdP1owoSSzJ0M_PS8vUjAlwCfJwDgLZH4dVvYYyhANODYAV4fBCcWKRfkBsaUeWTFuyp66gIABC_KT0%21/dz/d5/L0lHSkovd0RNQU5rQUVnQSEhLzROVkUvZW4%21/)، [لائحة النقل](https://dgp.sdaia.gov.sa/wps/portal/pdp/knowledgecenter/details/RegulationonPersonalDataTransferOutsidetheKingdom/%21ut/p/z1/jZDLDoIwEEW_hQ8wLTSgLvGRCIiiPMRuTBNKaQKFQHHh11tZSgRnN8m5mTkXYJACLMiTMyJ5LUip9ju2Ho69tw56CA092ZjQQv7JND1kwGgJbl9AnKwVcDF813YQDBDA_-Thj7HhXN6dA5SB0fpbnwHcEFksuMhrkF4p68tBshYBbbuP7I5IErVEdDltz73seEZlQT0uWFZX6lE8eWqFRsC4iwGYkG2qOH0d89BhmvYGeqrWEA%21%21/dz/d5/L0lDUmlTUSEhL3dHa0FKRnNBLzROV3FpQSEhL2Vu/)).
3. **جودة المصدر:** الاتصال الناجح لا يعني بيانات صحيحة. نحتاج checks للتوازن، التسلسل، التكرار، العملة، المنطقة الزمنية، وفترات النقص.
4. **سرقة الأسرار:** مفاتيح Odoo وQoyod ليست «إعداداً بسيطاً»؛ تعامل ككلمات مرور، بصلاحيات قليلة، تشفير، rotation وسجل وصول.
5. **الكتابة المبكرة:** أي auto-posting خاطئ يضر دفاتر العميل. ابدأ قراءة ومقترحات فقط، ثم write-back محدود مع موافقة وحدود وتراجع.
6. **فواتير ZATCA:** لا نعيد اختراع إصدار الفواتير. إن دخلنا هذه الطبقة، نلتزم بمواصفات API والأمن والـSDK الرسمي ([ZATCA](https://zatca.gov.sa/en/E-Invoicing/SystemsDevelopers/Pages/Simplified-technical-guide.aspx)).

## الرأي النهائي

ميزة NOVA ليست «عدد التكاملات». ميزتها أن تجعل البيانات المتفرقة **قراراً مالياً موثوقاً بلا متابعة بشرية يومية**. لذلك:

> **اشترِ الأنابيب المنظّمة، وابنِ العقل المالي.**

ابدأ بشريحة واحدة، مصرفية مفتوحة عبر شريك، موصلين محليين عميقين، ومحرك مطابقة واستثناءات قوي. إذا حقق المنتج تغطية بيانات يومية ومطابقة عالية دون تدخل، توسّع بعدها. أما بناء عشرات الموصلات أو وكيل سطح مكتب من البداية فسيحوّل الشركة إلى فريق صيانة تكاملات قبل إثبات قيمة المنتج.
