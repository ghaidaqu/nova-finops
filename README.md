# NOVA

> اعرف أين ذهب مالك، قبل أن يصبح الفرق مشكلة.

منصة عربية (RTL) لمطابقة أموال الأعمال السعودية في أي قطاع: ترفع ملفات التصدير من أنظمتك (المبيعات، بوابة الدفع، كشف البنك)، فنطابقها تلقائيًا ونخبرك بما لم يصل، وما وصل ناقصًا، والرسوم الزائدة، والتكرارات.

## كيف تعمل المطابقة

كل مصدر له نوع:

| النوع | أمثلة |
| --- | --- |
| مبيعات وفواتير | نقاط البيع، المتجر الإلكتروني، الفواتير، تطبيقات التوصيل |
| بوابة دفع أو منصة | تقارير بوابات الدفع والمنصات التي تحصّل نيابة عنك |
| كشف بنك | ما وصل فعلًا إلى حسابك |
| مصاريف وتكاليف | الرواتب والإيجار والموردين: لا تدخل المطابقة، ومنها نحسب صافي الربح وهامشه |

نطابق المبيعات مع بوابة الدفع (أو مع البنك مباشرة إن لم توجد بوابة)، ثم البوابة مع البنك: بالمرجع، ثم بالمبلغ داخل مدة الوصول، ثم بمجموع أيام كاملة (التحويلات المجمعة). المنطق في [lib/reconcile.ts](lib/reconcile.ts).

مصدر المبيعات يصل ماله إما عبر بوابة الدفع أو مباشرة إلى البنك (مثل تطبيقات التوصيل بعد العمولة)، ويُحدد ذلك من إعدادات المصدر. المبيعات النقدية لا تدخل المطابقة، ومدة الوصول تُحسب بأيام العمل (الجمعة والسبت عطلة).

| التنبيه | معناه |
| --- | --- |
| مبلغ لم يصل | مبيعات تجاوزت مدة وصولها ولا يقابلها شيء |
| دفع ناقص | وصل مبلغ أقل من المتوقع: مؤكد عند تطابق المرجع، و«محتمل» عند المطابقة بالمبلغ والتاريخ |
| رسوم زائدة | رسوم البوابة أعلى من النسبة المتفق عليها في إعدادات المصدر |
| تكرار | نفس المرجع والمبلغ مرتين في مصدر واحد |
| وارد غير معروف | مبلغ وصل للبنك بلا بيع أو تسوية تقابله |

عند الاستيراد نتعرف على صف العناوين والورقة ونوع الملف والأعمدة، ونستبعد الصفوف الملغاة والفاشلة والمستردة وصفوف الأرصدة والإجماليات. ملفات الاختبار الواقعية (بنوك، بوابات دفع، متاجر، نقاط بيع، تطبيقات توصيل، محاسبة) في [tests/fixtures/imports](tests/fixtures/imports).

**حدود معروفة في النسخة التجريبية:** لا توجد استعادة كلمة المرور بالبريد (يمكن تغييرها من الإعدادات)؛ المتاجر التي تُغلق بعد منتصف الليل قد تظهر لها فروقات إن لم يحتو ملف نقاط البيع على «تاريخ العمل»؛ نطابق أحدث 60,000 عملية في مساحة العمل.

## التجربة محليًا

يتطلب Node.js ‏22.13 أو أحدث.

```sh
npm run install:ci        # تثبيت الحزم (مرة واحدة)
npm run db:migrate:local  # تجهيز قاعدة البيانات المحلية (بعد كل تحديث فيه migration جديد)
npm run dev               # http://localhost:5173
```

أنشئ حسابًا من `/signup`، ثم اختر «بيانات تجريبية» أو ارفع ملفاتك. ملفات جاهزة للتجربة في [public/samples](public/samples): `sales.csv` و`gateway.csv` و`bank.csv` و`expenses.csv`.

## الأوامر

```sh
npm test               # اختبارات المطابقة وقراءة الملفات
npm run lint           # فحص الكود
npm run build          # بناء نسخة النشر
npm run db:generate    # إنشاء migration بعد تعديل db/schema.ts
```

## البنية

- `lib/reconcile.ts`: محرك المطابقة (بدون اعتماديات، مختبر في `tests/`)
- `lib/parse-file.ts`: قراءة CSV وExcel والتعرف على الأعمدة العربية والإنجليزية
- `lib/import-rows.ts` و`lib/workspace-data.ts`: الحفظ في D1 وتجهيز بيانات الشاشات
- `lib/demo-data.ts`: النشاط التجريبي (وهو مصدر `public/samples` عبر `scripts/make-samples.mjs`)
- `app/api/`: الحسابات، الاستيراد، المصادر، التنبيهات، الإعدادات
- `components/nova/`: شاشات التطبيق ونافذة الاستيراد
- `components/prototype.tsx`: الصفحة التسويقية، الدخول، التهيئة، والإطار العام
- `docs/`: أبحاث السوق والمنتج، و`sites-starter.md` (توثيق القالب التقني)

مبني على [vinext](https://github.com/cloudflare/vinext) (Next.js على Cloudflare Workers) مع قاعدة بيانات D1. تفاصيل النشر في [docs/sites-starter.md](docs/sites-starter.md).

نسخة GitHub Pages (https://ghaidaqu.github.io/nova-finops/) واجهة ثابتة بلا خادم، فلا تعمل فيها الحسابات ولا الاستيراد.
